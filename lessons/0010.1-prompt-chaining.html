Prompt Chaining

Fase 1 · Lección extra 1.6.1 · ~14 min · Prompt Engineering

Algunas tareas son demasiado complejas para resolverlas con un único prompt fiable. Prompt chaining divide la tarea en sub-tareas más pequeñas: la salida de un prompt se convierte en la entrada del siguiente. Cada eslabón de la cadena hace una sola cosa bien, en vez de pedirle a un solo prompt que haga todo a la vez.

Por qué funciona Un prompt más pequeño y específico es más fácil de depurar, de evaluar y de optimizar por separado. Si la cadena falla, sabes exactamente en qué eslabón falló — algo casi imposible de diagnosticar en un prompt monolítico de 500 palabras.

Ejemplo: responder preguntas sobre un documento largo

1

Extraer las citas relevantes

Prompt 1: "Dado este documento y esta pregunta, extrae literalmente los fragmentos relevantes para responderla."

2

Redactar la respuesta

Prompt 2: "Usando solo estas citas extraídas, responde la pregunta original de forma concisa."

3

Verificar contra el documento

Prompt 3: "¿Esta respuesta está respaldada por las citas? Responde solo SÍ o NO y por qué."

Por qué no hacerlo en un solo prompt Si pides "lee el documento, extrae las citas, responde y verifica" en una sola llamada, el modelo tiende a saltarse pasos o a mezclar la extracción con la redacción, perdiendo la trazabilidad de qué parte del documento sustenta cada afirmación.
Cuándo encadenar en vez de usar un prompt único Cuando la tarea tiene fases claramente distintas (extraer → transformar → verificar), cuando necesitas inspeccionar resultados intermedios, o cuando cada fase requiere un nivel de "creatividad" distinto (temperatura baja para extracción, alta para redacción).
