Automatic Prompt Engineer y Active-Prompt

Fase 1 · Lección extra 1.6.5 · ~14 min · Prompt Engineering

Las lecciones 1.1 a 1.6 trataron el diseño y refinamiento de prompts como un proceso manual. Estas dos técnicas lo automatizan parcialmente, usando al propio LLM como herramienta de optimización.

Automatic Prompt Engineer (APE)

APE trata el diseño de instrucciones como un problema de búsqueda: usa un LLM para generar muchas variantes candidatas de una instrucción a partir de unos pocos ejemplos input/output, las evalúa contra un criterio objetivo, y se queda con la que obtiene mejor puntuación.

1

Generar candidatos

Un LLM "propone" decenas de instrucciones distintas que podrían producir los ejemplos de output dados los inputs.

2

Evaluar cada candidato

Cada instrucción candidata se ejecuta contra un set de validación y se puntúa (exactitud, formato, etc.).

3

Seleccionar y refinar

La mejor instrucción se selecciona; opcionalmente se generan variaciones de ella para una segunda ronda de búsqueda.

Prompt para que el LLM proponga instrucciones (meta-nivel) Aquí hay varios pares de entrada/salida. Genera 10 instrucciones distintas que, si se le dieran a un asistente, producirían esa salida a partir de esa entrada:

Entrada: "2, 4, 6, 8" → Salida: "10, 12, 14, 16"
Entrada: "1, 3, 5" → Salida: "7, 9, 11"
Relación con lo aprendido en 1.6 APE automatiza exactamente el bucle de refinamiento iterativo de la lección 1.6 (definir criterio → generar variantes → evaluar → quedarse con la mejor), pero delegando la generación de variantes al propio modelo en lugar de hacerlo a mano.

Active-Prompt

Few-shot y CoT funcionan mejor con buenos ejemplos anotados — pero anotar manualmente cadenas de razonamiento para cada tarea nueva es caro. Active-Prompt selecciona automáticamente qué ejemplos merece la pena anotar: genera varias respuestas para cada pregunta candidata sin anotar, mide el desacuerdo entre ellas (incertidumbre), y prioriza para anotación humana las preguntas donde el modelo está más "confundido".

Esquema de selección por incertidumbre Pregunta A → 5 respuestas generadas → 5/5 coinciden → baja incertidumbre, no prioritaria
Pregunta B → 5 respuestas generadas → 2/5 coinciden → alta incertidumbre, prioritaria para anotación humana con CoT

→ Las preguntas tipo B se convierten en los ejemplos few-shot de la próxima ronda.
